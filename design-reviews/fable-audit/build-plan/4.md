### M3 — Make the game-over review box show its whole lesson
**Where:** Game-over screen · `.missed-review` (REVIEW MISSED COMMANDS box) · all widths (768, 1440 confirmed clipped; 375 confirmed non-growing/no-affordance).

**What (mockup-ready):** Keep `.missed-review` at its current `max-height:220px` footprint (no layout expansion — Craft/Cohesion floor), but make the internal scroll legible instead of silent. Add a top and bottom fade mask (linear-gradient from the box's background color to transparent, ~24px tall) pinned to the top and bottom edges of the scroll container whenever content overflows — the fade only renders when `scrollHeight > clientHeight`, so a short list (like the seeded 375 case with two entries) shows zero fade and zero clipping cue. When the fade is present at the bottom, add a small static "scroll for more" affordance directly under it: a thin down-chevron or the text "↓ more" in muted graphite, phosphor-teal on focus/hover, sitting just inside the box's bottom padding — not overlapping the last visible line. Text itself is NEVER hard-clipped mid-glyph: the last fully-visible line inside the viewport must end at a natural line-height boundary (this is a CSS overflow fix — `overflow-y:auto` with the existing `scrollbar-width:thin`, not a text-truncation trick — so the browser's own line box, not a fixed pixel cut, decides where content breaks). On scroll to bottom, the bottom fade and affordance fade out (top fade appears once scrolled down at all), giving a clear "you've seen everything" signal.

**Why:** Resolves L2-F3 (768__opener: text sliced horizontally through glyph tops, no scrollbar/fade/more-cue visible; 1440: lesson trails off mid-sentence at "…skips the list and") and L5-F3 (`.missed-review` confirmed at index.html:966-970 as `max-height:220px; overflow-y:auto; scrollbar-width:thin`, with 375__opener byte-identical to 375__full proving the box never grows to reveal clipped content — the container is present but silent). Both findings note the fix is bounded, not structural: "visible scroll affordance / gradient fade" (L5-F3 note) — this proposal delivers exactly that. Serves LEARNING directly: the results screen is the retention surface, and a silently-clipped explanation is a broken teaching moment on the single most load-bearing element of the screen. Serves the taste anchor: a fade mask + minimal affordance is restrained, editorial (echoes a reading-list "more below" convention), and closes an "edge-case negligence a reviewer spots in ten seconds" gap without adding visual noise.

**Player/Learner impact + Craft/Cohesion:** A player who misses several commands in one run now gets the full, correct lesson for every miss instead of a truncated fragment — closing a real learning gap, not just a cosmetic one. The fade + chevron is a small, confident, professional detail exactly where a portfolio reviewer's eye lands last on the results screen; it converts an "edge case bug" into a "they thought about this" moment.

**Accessibility note:** Not color-alone — the affordance uses a chevron glyph + text label, not fade opacity alone, to signal scrollability; fade is a pure visual polish layer, never the sole indicator (the scrollbar itself, kept via existing `scrollbar-width:thin`, remains the functional indicator). Keyboard: the scroll container must remain a normal focusable/scrollable region (arrow keys / Page Down / spacebar scroll it when focused, per native `overflow-y:auto` behavior) and must NOT trap focus — Tab must always be able to move past it to the next control (e.g. drill-missed / play-again buttons) regardless of scroll position. No photosensitivity concern (no flashing/strobing; fade is a static gradient, not animated). Reduced motion: if the fade/affordance opacity is animated in/out on scroll, that transition must be suppressed under `prefers-reduced-motion: reduce` (fade/affordance simply show/hide instantly, no easing) — scrolling itself (a user-initiated, non-decorative motion) is exempt per standard RM practice.

**Effort:** S — pure CSS (gradient mask via `mask-image` or a layered pseudo-element, JS toggle on scroll-position/overflow-detect) on an existing, isolated component; no markup restructuring, no protected-list changes. No conflicts with other proposals (touches only `.missed-review` presentation, not `renderExplain` or any PROTECT item).
